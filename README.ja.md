# FBConsole — Firebird 5用管理ツール（開発版0.3.40）

Lazarus / Free Pascalで新規作成したデスクトップアプリです。
IBConsole日本語版+αユーザーガイドを参照し、メニュー・上部ツールバー・左ツリー・右一覧・
下部ステータスを参考にしています。登録／接続ダイアログと対話型SQLは別ウィンドウです。
IBOConsoleの実行ファイル、画像、翻訳ファイル、コードは製品に取り込んでいません。
現時点ではIBOConsoleの全機能を置き換える完成版ではありません。
オープンソース版IBConsoleの参照先と機能の対応状況は
[IBCONSOLE-REFERENCE.md](IBCONSOLE-REFERENCE.md)にまとめています。

## 0.3の追加内容

0.3.20ではサーバーメニューに登録／登録解除、サービスマネージャーへのログイン／ログアウト、DB切断、ユーザー情報、ログファイル表示、サーバープロパティを追加しました。プロパティ画面ではエイリアス、ホスト、TCPポート、説明を編集できます。0.3.19のDB作成／削除と0.3.18のメイン画面も含みます。

資料の機能のうち、limbo回復は未実装です。詳細は[対応表](IBCONSOLE-REFERENCE.md)を参照してください。

0.3.9では、ISQLを参考にインタラクティブSQL画面を再構成しました。左側にテーブル／ビューと
フィールド一覧、右側にクエリビルダー／SQLタブ、下側にデータ／計画／統計／SQLログのタブを配置しています。
クエリビルダーは項目追加、別名、テーブル別名、ソート、集計関数、グループ指定からSELECTを生成します。
操作アイコンは高解像度で描画し、Windowsアプリのアイコンを追加しました。
添付の参考アイコンに寄せ、左にFirebirdの丸い鳥マーク、右に縦型サーバーを配置しました。
画像素材: [プレビュー](assets/FBConsole-app-icon-preview.png) / [Windows ICO](assets/FBConsole.ico)
再ビルドは build-windows.ps1 を実行します。

0.3.1では「SQL Statements」をSelect／Insert／Update／Deleteの切替タブにしました。
SQLは色分けし、SELECTは主キー順で並べ、UPDATE／DELETEは主キー条件を生成します。
主キーがない表ではUPDATE／DELETEを生成せず、ビューはSELECTのみです。
INSERT／UPDATEは計算列・IDENTITY列を除きます。パラメーター値は利用時に指定するテンプレートです。
構文色分けにはLazarus同梱のSynEditを使用します。

- コンパクトなサーバーログイン画面。ロール名の大文字小文字を選択できます。
- Servers → サーバー → データベース → DB → オブジェクトというツリー。
  DB選択時は右側をアクション／詳細一覧に切り替え、右クリックメニューも切り替えます。
- ツールバー、ツリーアイコン、サーバー／DB／ユーザーのステータス表示。
- テーブル専用ウィンドウ: プロパティ、データ、メタデータ、権限、依存関係、詳細、SQL Statements。
- カラムは型名、文字セット、照合、デフォルト値、Null可を表示します。
  インデックス、一意制約、チェック制約、参照制約、トリガーはプロパティ内で切り替えます。
- 主キーのある通常テーブルでデータの追加／更新／削除、フォーム表示、レコードコピー、CSV出力。
  「適用／確定」で保存し、「取り消し」で未保存の編集を破棄します。
- バックアップ、新規DBへの復元、スイープ、修復を行わない検証、サーバーログ。
  管理操作はログイン情報を再入力し、別スレッドで進捗を表示します。
  ファイルパスはすべてサーバー上のパスです。
- DBプロパティ、接続中ユーザー、監視統計、ユーザー一覧。
- DBノードの「メタデータの表示」から、ドメイン、テーブルと主キー／一意制約、
  ビュー、シーケンス、例外、オブジェクトソース、権限をSQL形式で確認できます。
  専用ウィンドウで全体コピーまたはUTF-8ファイル保存ができます。

テーブル画面は独立したトランザクションを使用します。
対話型SQLのコミットボタンでテーブル画面の編集が確定されることはありません。
編集できるのは先頭1000行で、ビュー、主キーのない表、未対応の主キー型の表は参照のみです。
新データ型・BLOB・生成列は参照のみです。編集適用時にエラーが発生した場合は、
その画面の編集トランザクションを取り消して再表示します。
テーブル画面の参照用DDLは列定義のみです。DBノードの「メタデータの表示」は
複数のオブジェクト定義を抽出しますが、全属性・依存順を含む完全な復元スクリプトではありません。

## 起動

ビルドすると `bin/FBConsole-0.3.40.exe` が生成されます。
Windows GUI形式でビルドしているため、起動時にターミナルウィンドウを作成しません。
IBConsoleを参考に42種類のアイコンを新規描画し、ツールバーは32px、ツリー／メニューは24pxで表示します。
ツールバー、ツリー、操作一覧、右クリックメニュー、テーブルのタブと操作ボタンに割り当てています。
接続中／未接続のサーバーとDBは異なるアイコンで表示します。
「登録…」から接続先を登録し、「この接続設定を登録する」を選択します。
登録後にツリーでDBを選んで接続アイコンを押すと、ログイン画面が開きます。接続先の設定項目は次のとおりです。

- Firebird 5の64ビット版 `fbclient.dll` のフルパス。
- 接続方法: ローカルサーバー（TCP/IP）、リモートサーバー（TCP/IP）、接続文字列を直接指定。
- リモート接続ではホスト名／IPv4／IPv6とポートを別々に入力します。既定ポートは3050。
- DBの別名、またはサーバー上のパス。クライアント側のファイルを選ぶ必要はありません。
  Linux例: `/var/firebird/timecard.fdb`、Windows例: `D:\Data\sample.fdb`。
- ユーザー、パスワード、必要ならSQLロール。

このPCで検証に使ったクライアント:
`E:\Program Files\Firebird\IBConsole\Firebird-5.0.4.1812-0-windows-x64\fbclient.dll`

クライアントはFirebirdの配布ディレクトリー内のものを指定してください。
DLL単体の配布・必要ランタイムの同梱はまだ行っていません。
接続時文字セットはUTF8、SQL方言は3です。
接続設定は実行ファイルと同じフォルダーの `config/connections.ini` に保存します。`config` フォルダーは起動時に作成します。フォルダーへの書き込み権限が必要です。
パスワードは保存しません。
初回は接続先が空です。以前のユーザー設定ディレクトリーやサンプル設定は自動で読み込みません。実行ファイルを更新しても、同じフォルダー内の `config/connections.ini` を引き続き使います。
登録は複数保存できますが、接続中に別の登録済みDBへ接続すると同じメイン画面のツリーに接続を表示します。ログイン後も元のDBのSQL・編集を続けられます。
切り替えをキャンセルした場合は、既存の接続を維持します。

### Timecardリモート接続

`connections.example.ini`に次の接続設定を用意してあります。
このファイルは参考用です。起動時には読み込まれません。必要な場合は次の内容で接続先を登録してください。

- 接続方法: リモートサーバー（TCP/IP）
- サーバー: `db.example.test`
- ポート: `3050`
- データベース: `/var/firebird/timecard.fdb`
- ユーザー: 初期値は`SYSDBA`。実際の接続ユーザーに変更してください。

「Timecard」を選んで「接続…」を押し、ユーザー名とパスワードを入力します。
接続先の確認欄に`inet://db.example.test:3050//var/firebird/timecard.fdb`と表示されます。
Linuxの絶対パスなのでポートの後の`//`は正しい表記です。
接続書式は[Firebird公式ガイド](https://firebirdsql.org/file/documentation/html/en/firebirddocs/qsg5/firebird-5-quickstartguide.html)に準拠します。

## 操作

- 左のツリー: サーバー → データベース → オブジェクトの種類 → 名前。
- 右の一覧: 左で選んだ階層の項目を名前・種類・状態で表示。ダブルクリックで開きます。
- 切断後も登録済みサーバーとDBをツリーに保持します。
- テーブル／ビューをダブルクリック: 専用のプロパティ画面を開きます。
  「データ」タブで先頭1000行を表示します。
- 「構造・定義」: 選択したテーブルの列情報、プロシージャ等のソース、シーケンスの現在値など。
- 「対話型SQL」: ISQL風のオブジェクト／フィールド一覧、クエリビルダー、SQL欄、結果タブを備えた独立画面です。
  クエリビルダーは基本的なSELECT/FROM/GROUP BY/ORDER BYを生成します。
  「前処理」で実行計画を確認できます。「全件取得」で残りの行を読み込み、「印刷」でSQL本文を印刷できます。名前付きパラメータ（例：:id）の値は実行時に入力します。
  SQLを1文ずつ実行。SELECTやRETURNINGなど結果を返す文はチェックを入れ、
  DDLや通常のINSERT/UPDATE/DELETEはチェックを外して実行します。
- 更新は「コミット」で確定し、「ロールバック」で取り消します。
  SELECTにも副作用があり得るため、すべての実行後に未確定と表示します。
  切断・終了時に未確定のSQLがある場合はロールバックするか確認します。
  SQL本文のCOMMIT/ROLLBACK/トランザクション開始文は使用せずボタンを使ってください。
- CSV出力は表示中の最大1000行のみ。UTF8、全セル引用符付き。
  NULLは`<NULL>`、バイナリBLOBは`<BLOB>`という表示用表現です。
  データベースの完全なエクスポート形式ではありません。
- SQLメニューでUTF8のSQLファイルを開く／保存できます。

## Firebird 5のデータ型

FPC 3.2.2標準のSQLDBが直接扱えない型は、接続ごとの`SET BIND`でVARCHARとして取得します。
INT128、NUMERIC/DECIMALの38桁値、DECFLOAT(16/34)、TIME/TIMESTAMP WITH TIME ZONEが対象です。
数値をDOUBLEへ丸める互換設定は使用しません。
サーバーの格納型やグローバル設定は変更しません。
表示上は文字列のため、結果の数値ソートや型を保つ直接編集には未対応です。

仕様: [Firebird 5 SET BIND](https://firebirdsql.org/file/documentation/chunk/en/refdocs/fblangref50/fblangref50-management.html)

## ビルド

### Linuxデスクトップ（GTK2）

Linux用のLazarus、Free Pascal、LCLのGTK2ユニット、SynEdit、Printer4Lazarusが必要です。ソースをユーザーが書き込める場所に置き、FBConsoleフォルダーで実行します。

```sh
sh build-linux.sh
./bin/FBConsole-0.3.79
```

接続設定のクライアントライブラリには、Linux側にインストールしたFirebird 5クライアントの `libfbclient.so` または `libfbclient.so.2` のフルパスを指定してください。DBパスには、接続先サーバー上のパスまたは別名を指定します。
設定ファイルは実行ファイルの隣の `config/` に保存します。メイン画面を撮影する場合は、デスクトップ上で `./bin/FBConsole-0.3.79 --capture-main ./main.png` を実行します。出力先には新しいファイル名を指定してください。

### Windows

Lazarusで`FBConsole.lpi`を開いてビルドします。追加の外部コンポーネントは不要です。

```powershell
& 'E:\Program Files\lazarus\lazbuild.exe' --build-all FBConsole.lpi
```

Windows x86_64 / FPC 3.2.2でコンパイル確認済みです。
他OS／32ビット版は未検証です。

## 主な制限

- SQLスクリプトは複数文を順番に実行し、`SET TERM`で区切り文字を切り替えられます。エラーが出た時点で停止し、先行文の実行結果は通常のトランザクション規則に従います。複数の結果セットは最後の結果だけを表示します。
- 初期結果は最大1,000行です。全件取得は結果をグリッドに保持するため、大量データでは時間とメモリを使います。
- 実行中のSQLキャンセルとSQLのバックグラウンド実行は未実装です。長時間SQLでは画面が応答しない場合があります。
- テーブルのデータ画面ではBLOBセルのダブルクリックで内容を表示し、元データをファイルへ保存できます。配列型は専用表示・編集に対応していません。SQL実行結果のBLOB列は簡易表示です。
- パッケージ内の関数・プロシージャは個別一覧とソース参照に対応しましたが、引数定義や依存関係を含む復元用DDLは生成しません。
- メタデータ表示はドメイン、テーブル、制約、ビュー、インデックス、シーケンス、ルーチンのソースなどを抽出します。全属性と依存順を再現するバックアップ用DDLではありません。
- SQLDBの制約により、INT128、DECFLOAT、タイムゾーン付き日時は文字列として取得します。表示精度は保ちますが、型としての編集や集計・並べ替えはできません。
- ツリーで接続済みDBを選択して切り替えます。各DBの切断・確定操作はその接続だけに適用されます。テーブル画面の編集トランザクションはSQL画面と独立しています。
- Limboトランザクションの回復には対応していません。
- バックアップ等の管理サービスは別スレッドで実行します。
